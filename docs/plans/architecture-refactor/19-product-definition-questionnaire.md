# 19 — 产品定义澄清问卷 (B4a 产品定义加锁)

> **用途**: Round 18+ 外部审计发现产品定义有战略性歧义,但 22 crate 架构已规划。必须在 C/A 启动前,由**业务方 + 产品负责人**锁死以下 15 个问题,否则架构有 20-30% 方向错的风险。
>
> **状态**: v0.1 问卷版 (2026-04-24)。答案回填后升 v1.0, 作为 [15 产品北极星 v1.2](15-product-north-star.md) 的前置。
>
> **使用方式**: 业务方与技术架构师一起逐题回答, 每题必须给出**确定性答案**, 不允许"TBD"或"看情况"。

---

## 第一组: 用户画像 (3 题)

### Q1. 产品的**直接使用者**是谁?

- [ ] A. 企业内部开发者 (类似 Claude Code / Cursor 定位)
- [ ] B. 企业内部业务人员 (HR / 财务 / 法务, 无代码使用 AI Agent)
- [ ] C. 企业 IT 运维 (部署/管控其他人用 Agent)
- [ ] D. 三者都是 (平台型, 角色通过权限区分)
- [ ] E. 其他: _________

**影响**: A→重投 TUI/CLI; B→重投可视化编辑器; C→重投管理后台; D→全都做但优先级必须排

### Q2. 使用者的**技术水平假设**?

- [ ] A. 都会写代码, 能看懂配置文件
- [ ] B. 部分会写代码 (业务+开发混用)
- [ ] C. 完全不懂代码, 靠拖拽/对话

**影响**: C 意味着 W_Q3 可视化编辑器**必须前置到 MVP**, 不是 Y1 Q3

### Q3. 典型**使用场景**是什么? (选 2-3 个主线)

- [ ] A. 辅助编程 (code review / 生成 / 重构)
- [ ] B. 内部数据分析 (HR 薪酬 / 财务报表 / 法务合规)
- [ ] C. 流程自动化 (RPA 类 / 工单处理)
- [ ] D. 智能客服 / 知识问答
- [ ] E. 内容生成 (报告 / 邮件)
- [ ] F. 其他: _________

**影响**: 决定 skills / tools / channels 的优先投入

## 第二组: 竞品对标 (3 题)

### Q4. 真实的**商业竞品**是哪些? (选 2-3 个)

- [ ] A. **Anthropic Claude Code** (开发者 CLI)
- [ ] B. **Cursor** (AI IDE)
- [ ] C. **Dify** (LLM 应用开发平台)
- [ ] D. **字节扣子** (Agent 创建平台)
- [ ] E. **智谱清影** / 智谱 MaaS 平台
- [ ] F. **钉钉 AI 助理** / 腾讯 AI 助手
- [ ] G. **国产化自研 (中科闻歌 / 第四范式 / 百度千帆)**
- [ ] H. 其他: _________

**警告**: 如果选的**不包含 A**, 则 [14 Claude Code 对标文档](14-claude-code-capability-parity.md) 需改名为"技术能力参考清单", 并新增一份对真实竞品的对标文档。

### Q5. 客户决策时**最关键的差异化能力**是什么? (按重要度排序 3 个)

- [ ] 1️⃣ 国密/信创合规
- [ ] 2️⃣ 组织管控/审计完整性
- [ ] 3️⃣ 私有化部署/数据不出企业
- [ ] 4️⃣ 国产 LLM 多家适配
- [ ] 5️⃣ 多沙箱安全纵深
- [ ] 6️⃣ DLP 敏感数据防泄漏
- [ ] 7️⃣ 可视化 Agent 编辑 (无代码)
- [ ] 8️⃣ Skills Marketplace
- [ ] 9️⃣ WASM 插件安全
- [ ] 🔟 其他: _________

**影响**: MVP 首秀应该押宝前 2 个能力, 其他可 M2/M3

### Q6. 与竞品的"价格带"关系?

- [ ] A. 比竞品贵 30%+ (走高端国央企)
- [ ] B. 与竞品持平
- [ ] C. 比竞品便宜 30%+ (走中端)
- [ ] D. 免费/开源, 靠服务赚钱

**影响**: A/D 架构完全不同, D 必须现在就考虑开源治理

## 第三组: 商业模式 (3 题)

### Q7. 交付模式是?

- [ ] A. **私有化部署** (客户机房, 一次性+维护费)
- [ ] B. **专属 SaaS** (我们托管, 客户独立实例)
- [ ] C. **多租户 SaaS** (共享实例)
- [ ] D. **开源+商业版**
- [ ] E. 其他: _________

**影响**: C 要重做多租户隔离架构; D 要重做 License + contribution 治理

### Q8. 单客户**典型规模**?

- [ ] A. 单机 1 人用 (桌面客户端为主)
- [ ] B. 小团队 10-50 人
- [ ] C. 中型 100-500 人
- [ ] D. 大型 1000-10000 人
- [ ] E. 超大型 10000+ 人

**影响**: D/E 需要组织树/权限/配额复杂度远超当前设计

### Q9. **计费模型**?

- [ ] A. 按 seat (每个用户月费)
- [ ] B. 按 LLM token 量
- [ ] C. 按 Agent 数量
- [ ] D. 按 API 调用量
- [ ] E. 年度 License (买断制)
- [ ] F. 不收费 (内部使用/战略产品)

**影响**: A/B/C/D 都需要计量埋点架构,F 不用; B 需要精确 token 追踪 (已部分在 `rollout-trace`)

## 第四组: 合规与部署 (3 题)

### Q10. 必须满足的**合规标准**? (多选)

- [ ] A. 等保 2.0 三级
- [ ] B. 等保 2.0 四级
- [ ] C. 信创白名单 (芯片/OS/数据库国产)
- [ ] D. 密评 (GM/T 0054)
- [ ] E. GDPR
- [ ] F. HIPAA (医疗)
- [ ] G. SOC2
- [ ] H. 仅内部规范, 无外部合规

**影响**: A-D 决定 W0 必须包含什么; E-G 影响数据本地化策略

### Q11. **目标部署环境** 的操作系统?

- [ ] A. Linux 服务器 (麒麟/统信/RHEL/Ubuntu)
- [ ] B. Windows Server
- [ ] C. Windows 10/11 桌面
- [ ] D. macOS 桌面
- [ ] E. 国产麒麟/统信 桌面
- [ ] F. 混合 (客户端多平台, 服务端单平台)

**影响**: C/D/E 决定 desktop-client 的适配优先级; 当前 [17 §5](17-crate-inventory-audit.md) 规划三平台沙箱 (W7), 但如果只卖服务端 A, Windows/macOS 沙箱可以 Y2 再做, **节省 9753 行 Windows 沙箱 port**

### Q12. 是否需要**国密硬件**?

- [ ] A. 必须支持实体 USB Key (SKF 接口)
- [ ] B. 必须支持 TPM / HSM
- [ ] C. 软件实现国密算法即可 (SM2/SM3/SM4 算法级合规)
- [ ] D. 不需要国密

**影响**: A/B 决定 [18 §4 风险矩阵](18-execution-roadmap.md)里 "国密硬件缺失" 的严重程度; C 大幅降低 W0 复杂度

## 第五组: 规模与时间 (3 题)

### Q13. 团队**当前 Rust 工程师规模**?

- [ ] A. 1-2 人
- [ ] B. 3-5 人
- [ ] C. 6-10 人
- [ ] D. 10+ 人

**影响**: [18 §2](18-execution-roadmap.md) 设定的 Wave 人力假设 W0 需 4 人、W6 峰值 7 人并行、W7 沙箱 3 人。A/B 档要把路线图时间乘 2-3 倍。

### Q14. **团队 Rust 经验**?

- [ ] A. 大部分有 3+ 年经验
- [ ] B. 有 1-2 人资深 + 其余新手
- [ ] C. 团队整体 < 1 年 Rust 经验

**影响**: C 意味着 port codex 代码时踩坑率极高,预估工期再 +50%

### Q15. **最晚交付时间**?

- [ ] A. 今年 Q2 末必须 MVP (激进)
- [ ] B. 今年 Q3 末 MVP (合理)
- [ ] C. 今年 Q4 末 MVP (宽松)
- [ ] D. 明年上半年 MVP 即可 (宽松)

**影响**: A 必须砍 MVP 范围到最少 (例: 只做 2 个 P0 能力); D 可按 [18](18-execution-roadmap.md) 完整规划推进
