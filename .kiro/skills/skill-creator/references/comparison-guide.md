# 盲评对比指南

> 本文档改编自 Anthropic 官方 skill-creator 的 comparator 和 analyzer agent 指令。
> 原版由独立的 subagent 执行盲评，Kiro 版由 AI 在对话中直接执行。

## 盲评角色

对比两个输出，不知道哪个 skill 产生了哪个。你收到两个标记为 A 和 B 的输出，但你不知道哪个 skill 产生了哪个。这防止了对特定 skill 或方法的偏见。

你的判断纯粹基于输出质量和任务完成度。

## 盲评流程

### 1. 阅读两个输出

1. 检查输出 A
2. 检查输出 B
3. 记录每个的类型、结构和内容

### 2. 理解任务

1. 仔细阅读评估提示
2. 识别任务要求：产出什么？什么质量重要？什么区分好输出和差输出？

### 3. 生成评估量规

基于任务，生成两个维度的量规：

**内容量规**（输出包含什么）：

| 标准 | 1（差）| 3（可接受）| 5（优秀）|
|------|--------|-----------|---------|
| 正确性 | 重大错误 | 轻微错误 | 完全正确 |
| 完整性 | 缺少关键元素 | 大部分完整 | 所有元素都有 |
| 准确性 | 显著不准确 | 轻微不准确 | 全程准确 |

**结构量规**（输出如何组织）：

| 标准 | 1（差）| 3（可接受）| 5（优秀）|
|------|--------|-----------|---------|
| 组织性 | 杂乱无章 | 合理组织 | 清晰、逻辑结构 |
| 格式 | 不一致/破损 | 大部分一致 | 专业、精致 |
| 可用性 | 难以使用 | 需要努力才能用 | 易于使用 |

根据具体任务调整标准。比如：
- PDF 表单 → "字段对齐"、"文本可读性"、"数据放置"
- 文档 → "章节结构"、"标题层级"、"段落流畅度"
- 数据输出 → "Schema 正确性"、"数据类型"、"完整性"

### 4. 评分

对每个输出（A 和 B）：
1. 对量规的每个标准评分（1-5）
2. 计算维度总分
3. 计算综合分数：维度分数的平均值，缩放到 1-10

### 5. 检查断言（如果有）

如果提供了断言：
1. 对输出 A 检查每个断言
2. 对输出 B 检查每个断言
3. 断言分数作为辅助证据（不是主要决策因素）

### 6. 确定赢家

按优先级对比 A 和 B：
1. 主要：综合量规分数
2. 次要：断言通过率
3. 平局打破：如果真的相等，宣布平局

要果断——平局应该很少见。

## 事后分析

确定赢家后，"揭盲"结果，分析 skill 和执行过程。目标是提取可操作的洞察。

### 分析流程

1. **阅读两个 skill**：识别结构差异——指令清晰度、工具使用模式、示例覆盖、边界情况处理
2. **阅读两个执行过程**：对比执行模式——每个多紧密地遵循了 skill 指令？使用了什么不同的工具？输家在哪里偏离了最优行为？
3. **分析指令遵循度**：评分 1-10，记录具体问题
4. **识别赢家优势**：什么让赢家更好？
5. **识别输家弱点**：什么拖累了输家？
6. **生成改进建议**：可操作的、按影响优先级排序的建议

### 改进建议类别

| 类别 | 描述 |
|------|------|
| `instructions` | 对 skill 文字指令的修改 |
| `tools` | 要添加/修改的脚本、模板或工具 |
| `examples` | 要包含的输入/输出示例 |
| `error_handling` | 处理失败的指导 |
| `structure` | skill 内容的重新组织 |
| `references` | 要添加的外部文档或资源 |

### 优先级

- **高**：可能改变对比结果
- **中**：会提升质量但可能不改变胜负
- **低**：锦上添花

### 输出格式

参见 `references/schemas.md` 中的 `analysis.json` 结构。

### 指导原则

- 要具体：引用 skill 和执行过程，不要只说"指令不清晰"
- 要可操作：建议应该是具体的修改，不是模糊的建议
- 聚焦 skill 改进：目标是改进输家的 skill，不是批评 AI
- 按影响排序：哪些改动最可能改变结果？
- 考虑因果关系：skill 的弱点是否真的导致了更差的输出，还是只是巧合？
- 考虑泛化：这个改进是否也会帮助其他评估用例？
